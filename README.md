# BT115 TV Helper

تطبيق Android TV صغير (Java/Android SDK) بواجهة عربية فيها زر **ابدأ الآن** وخيار **البدء مع تشغيل النظام**. أُعدّ للمصدر الذي يمكن رفعه إلى GitHub؛ الملف `.github/workflows/android.yml` يبني APK تجريبيًا تلقائيًا عند `push` إلى `main` أو `master`، أو عند تشغيل Workflow يدويًا.

## البناء من GitHub

1. أنشئ مستودعًا فارغًا في GitHub.
2. ارفع محتويات هذا المجلد إلى الفرع `main`.
3. افتح تبويب **Actions** وانتظر سير `Build Android TV APK`.
4. نزّل الملف من **Artifacts → bt115-tv-helper-debug-apk**. هذا APK تجريبي موقّع بمفتاح debug، وليس APK نظاميًا أو إصدارًا رسميًا موقّعًا بمفتاح جهازك.

## مهم جدًا: صلاحيات النظام

هناك فرق بين APK عادي وتطبيق نظام:

- الضغط على زر البدء يحاول تنفيذ الأوامر بالترتيب عبر `su -c` أولًا. إن لم ينجح، يحاول تنفيذها عبر shell الخاص بالتطبيق، وهو ما لن ينجح عادةً في APK عادي.
- يتضمن المستودع `Android.bp` وقائمة سماح `system/privapp-permissions-com.example.bt115helper.xml` للتحضير لدمج التطبيق داخل شجرة AOSP كـ `priv-app` موقّع بمفتاح `platform`.
- **ملف APK الذي يبنيه GitHub Actions ليس تطبيق نظام**. لا يستطيع GitHub استخدام مفتاح توقيع منصة Amlogic الخاص بجهازك، ولا يمكن لتطبيق sideload أن يمنح نفسه `BLUETOOTH_PRIVILEGED` أو `DELETE_PACKAGES`. يلزم مصنع الجهاز/معدّل firmware أو مطوّر ROM يدمج المصدر في شجرة النظام ويوقّعه بمفتاح المنصة المطابق، ثم يبني firmware/صورة نظام مناسبة لجهازك. قائمة السماح وحدها لا تمنح الصلاحية دون توقيع مناسب.
- خدمة Accessibility لا تمنح صلاحيات shell أو صلاحية توقيع النظام أو تجاوز قيود Bluetooth؛ لذلك لم أضف Accessibility Service مضللة أو غير لازمة.

خطوات AOSP عامة: انسخ مجلد المشروع إلى شجرة المصدر (مثل `packages/apps/BT115TvHelper`)، أضف `BT115TvHelper` إلى قائمة حزم المنتج (`PRODUCT_PACKAGES`)، ثم ابنِ صورة الجهاز باستخدام إعدادات ومفاتيح الشركة المصنّعة. قد تتطلب شجرة Amlogic تعديلات توافق إضافية.

## ما الذي يفعله التطبيق

- ينفذ عند الضغط على «ابدأ الآن»، بعد نافذة تحذير وتأكيد، هذه المحاولات بالترتيب:
  1. `cmd bluetooth_manager disable`
  2. `cmd bluetooth_manager enable`
  3. `pm clear com.android.bluetooth`
- خيار البدء عند الإقلاع يشغّل الخدمة بعد `BOOT_COMPLETED` إذا سبق أن حفظ المستخدم الخيار.
- يبدأ البحث عن أجهزة Bluetooth بالأسماء الدقيقة `BT115-001` و`BT115-002` و`BT115-003`. إذا عثر على جهاز غير مقترن، يطلب الاقتران عبر واجهة Android العامة؛ قد يحتاج المستخدم إلى قبول نافذة النظام أو إدخال PIN. لا يضمن Android الاقتران الصامت.
- يعرض إشعارات عن حالة البحث والاقتران واتصال/انقطاع ACL عندما يبلغ نظام Bluetooth عنها.

## آثار الأمر `pm clear`

`pm clear com.android.bluetooth` يمسح بيانات تطبيق/خدمة Bluetooth وقد يؤدي إلى حذف معلومات الاقتران أو إعادة ضبط إعداداته، وربما يحتاج الجهاز إلى إعادة اقتران الريموت. لهذا يظهر تحذير وتأكيد قبل التنفيذ اليدوي. عند تفعيل البدء التلقائي، ستُعاد المحاولات عند الإقلاع دون نافذة تأكيد؛ لا تفعّل الخيار إلا بعد فهم هذا الأثر وتجربة firmware على مسؤوليتك.

## ما لا يستطيع APK عادي فعله

Android لا يوفّر لتطبيق عادي واجهةً لفرض GATT connection priority/latency على ريموت HID، أو تعطيل مؤقتات LMP، أو جعل النظام يعلن أن جهازًا مفصولًا ما زال متصلًا. هذه ليست وظيفة Accessibility. كما أن أجهزة Android TV قد تقيّد تشغيل الخدمات عند الإقلاع أو البحث المستمر وفق firmware والطاقة.

المشروع يتعمد ألا يزوّر حالة الاتصال: إذا أعلن Android عن الانقطاع يعرضه، ثم يواصل البحث. نجاح التطبيق في تشغيل الأوامر واستخدامها يتوقف على صلاحيات root الفعلية أو دمج OEM الصحيح؛ لا تدّعي شاشة التطبيق أن APK العادي يملك تلك الصلاحيات.
